Fix Google authentication redirect on SkillSnap (skillsnap.com.au):

━━━━━━━━━━━━━━━━━━━━━━━
PROBLEM
━━━━━━━━━━━━━━━━━━━━━━━
When a user signs in or signs up using "Continue with Google", after successful authentication they are redirected back to the landing page (skillsnap.com.au) instead of the feed (skillsnap.com.au/feed).

━━━━━━━━━━━━━━━━━━━━━━━
FIX — code level only, no Supabase dashboard changes needed
━━━━━━━━━━━━━━━━━━━━━━━
Find the Google sign-in button and its Supabase auth call. It currently calls:

  supabase.auth.signInWithOAuth({ provider: 'google' })

Update it to include the redirectTo option:

  supabase.auth.signInWithOAuth({
    provider: 'google',
    options: {
      redirectTo: 'https://skillsnap.com.au/feed'
    }
  })

Apply this change to ALL instances of Google OAuth sign-in in the codebase — both the sign-in and sign-up flows if they are separate.

━━━━━━━━━━━━━━━━━━━━━━━
ALSO FIX — auth state listener
━━━━━━━━━━━━━━━━━━━━━━━
In the auth state change listener (onAuthStateChange), add a redirect to feed when a new session is detected and the user is currently on the landing page or login/signup page:

  supabase.auth.onAuthStateChange((event, session) => {
    if (event === 'SIGNED_IN' && session) {
      const currentPath = window.location.pathname
      if (currentPath === '/' || currentPath === '/login' || currentPath === '/signup') {
        router.push('/feed')
      }
    }
  })

This acts as a safety net to catch any auth flow that doesn't use the redirectTo option.

Do not change any UI, colours, fonts, or other functionality.
