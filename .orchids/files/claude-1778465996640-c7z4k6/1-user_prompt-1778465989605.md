Fix session hydration bug in SkillSnap (skillsnap.com.au):

━━━━━━━━━━━━━━━━━━━━━━━
PROBLEM
━━━━━━━━━━━━━━━━━━━━━━━
After Google OAuth login, the Supabase session token is correctly saved in localStorage. However when the app loads or navigates to the feed, AppState.tsx is not reading the existing session — treating the user as a guest despite being authenticated. This happens on both initial load and after navigation.

━━━━━━━━━━━━━━━━━━━━━━━
FIX — AppState.tsx initialisation
━━━━━━━━━━━━━━━━━━━━━━━
In AppState.tsx, on app initialisation (inside useEffect with empty dependency array), add a session check BEFORE rendering any UI:

1. Call supabase.auth.getSession() on mount:

  useEffect(() => {
    const initAuth = async () => {
      // Set loading state first
      dispatch({ type: 'SET_AUTH_LOADING', loading: true })

      // Check for existing session
      const { data: { session } } = await supabase.auth.getSession()

      if (session?.user) {
        // Session exists — hydrate profile and navigate to feed
        await hydrateProfile(session.user)
        dispatch({ type: 'NAVIGATE', screen: 'home' })
      } else {
        // No session — show landing page
        dispatch({ type: 'NAVIGATE', screen: 'landing' })
      }

      dispatch({ type: 'SET_AUTH_LOADING', loading: false })
    }

    initAuth()
  }, [])

2. Make sure onAuthStateChange listener handles SIGNED_IN correctly and does NOT conflict with the above getSession() call:
  - onAuthStateChange should only react to SIGNED_IN events that happen AFTER initial load
  - Use a flag (initialised = true after getSession resolves) to prevent double-firing

3. Add SET_AUTH_LOADING to the reducer if it doesn't exist:
  case 'SET_AUTH_LOADING':
    return { ...state, authLoading: action.loading }

4. While authLoading is true, render a minimal neutral loading screen — not the landing page and not the feed. Just a blank screen or a centred SkillSnap logo spinner. This prevents any flash of wrong content.
