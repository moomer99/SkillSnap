Fix profile creation for Google OAuth users in src/services/authService.ts:

━━━━━━━━━━━━━━━━━━━━━━━
PROBLEM
━━━━━━━━━━━━━━━━━━━━━━━
When a user signs in with Google for the first time, ensureProfile() fails to create a profile row because it uses getSupabase() (the proxy client) which does not share the authenticated session with getAuthSupabase() (the auth client). The upsert fails due to RLS policy rejecting the unauthenticated request, fetchProfile() also fails, and the function returns null — causing the app to treat the user as a guest.

━━━━━━━━━━━━━━━━━━━━━━━
FIX 1 — use getAuthSupabase() in ensureProfile and fetchProfile
━━━━━━━━━━━━━━━━━━━━━━━
In src/services/authService.ts, update both ensureProfile() and fetchProfile() to use getAuthSupabase() instead of getSupabase() for all database operations:

In fetchProfile():
  CHANGE: const sb = getSupabase()
  TO:     const sb = getAuthSupabase()

In ensureProfile():
  CHANGE: const sb = getSupabase()
  TO:     const sb = getAuthSupabase()

This ensures the database requests carry the authenticated session and pass RLS checks.

  if (error || !data) {
