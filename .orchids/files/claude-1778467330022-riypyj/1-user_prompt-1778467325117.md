Critical bug fix — Google OAuth login on SkillSnap (skillsnap.com.au):

━━━━━━━━━━━━━━━━━━━━━━━
PROBLEM
━━━━━━━━━━━━━━━━━━━━━━━
When a user clicks "Continue with Google" and completes Google authentication, they are redirected back to the landing page instead of the feed, and they appear as a guest (not logged in) despite the Supabase session token being correctly saved in localStorage.

Confirmed facts:
- The sb-auth-token IS saved in localStorage after Google auth completes
- No profile row is being created in the profiles table for Google users
- The RLS insert policy has been added manually in Supabase
- Previous fixes to authService.ts and AppState.tsx did not resolve the issue
- Email/password login works correctly and lands on feed

━━━━━━━━━━━━━━━━━━━━━━━
WHAT TO INVESTIGATE AND FIX
━━━━━━━━━━━━━━━━━━━━━━━
Please investigate the full Google OAuth callback flow end to end and fix all issues found. Specifically:

1. CHECK src/app/auth/callback/route.ts
   - Verify the PKCE code exchange is completing successfully
   - Verify it is correctly setting the session after exchange
   - Verify the redirect after callback goes to the correct screen (feed/home) and not landing page
   - Add console.error logging for any failures in the callback route
   - If the callback route is a server-side route, make sure it is correctly passing the session to the client

2. CHECK src/state/AppState.tsx
   - Verify the onAuthStateChange listener correctly handles INITIAL_SESSION and SIGNED_IN events after OAuth callback
   - Verify hydrateProfile is being called and completing successfully for Google users
   - Verify SET_AUTH is being dispatched correctly after profile hydration
   - Add console.log statements at each step so failures are visible in browser console

3. CHECK src/services/authService.ts
   - Verify ensureProfile() is successfully creating a profile row for Google OAuth users
   - Verify it is using getAuthSupabase() for all database operations
   - Add detailed console.log before and after the upsert so we can see if it is being called and what it returns

4. CHECK src/lib/supabase.ts
   - Verify getAuthSupabase() and getSupabase() are using the same storage key for session persistence
   - If they use different storage keys this will cause getAuthSupabase() to find the session but database queries to fail RLS
   - If storage keys differ, unify them to use the same key

5. TIMING ISSUE — check for race condition
   - The OAuth callback may be completing and redirecting to the app BEFORE onAuthStateChange fires
   - If AppState initialises and calls getUser() before the callback sets the session, it will find no user and show landing page
   - Fix: in AppState useEffect, after getUser() returns null, add a one-time listener for SIGNED_IN or INITIAL_SESSION to catch the late-arriving session from OAuth callback

6. After all fixes, verify the complete flow works:
   - User clicks Continue with Google
   - Google auth completes
   - Callback route exchanges PKCE code for session
   - Session is saved
   - App detects session
   - Profile row is created in profiles table
   - User lands on feed as authenticated user
   - Refreshing the page keeps the user logged in
