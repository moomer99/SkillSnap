ROOT CAUSE TO INVESTIGATE
━━━━━━━━━━━━━━━━━━━━━━━
The 400 error on the profiles query suggests either:
1. The query syntax is wrong (the jobs_done=gt.0 filter on the landing page feed query is a known 400 error — check if this is bleeding into the auth flow)
2. The authSb client does not have the correct session token when hydrateProfile runs immediately after SIGNED_IN
3. ensureProfile upsert is failing due to RLS or missing columns

FIX 2 — handle PGRST116 (row not found) separately from real errors
━━━━━━━━━━━━━━━━━━━━━━━
PGRST116 means "no rows found" — this is expected for new Google users and should NOT be treated as an error. Update hydrateProfile to handle this correctly:

  const { data, error: fetchErr } = await authSb
    .from("profiles")
    .select("*")
    .eq("id", userId)
    .single();

  if (data) {
    dispatch({ type: "SET_AUTH", user: mapProfile(data as Record) });
    return;
  }

  // PGRST116 = no rows found — expected for new users, proceed to ensureProfile
  // Any other error code = real problem
  if (fetchErr && fetchErr.code !== "PGRST116") {
    console.error("[AppState] unexpected profile fetch error:", fetchErr.message, fetchErr.code);
    dispatch({ type: "SET_AUTH_LOADING", loading: false });
    return;
  }

  // No profile row — create one
  console.log("[AppState] no profile row found, creating via ensureProfile");
  const user = await ensureProfile(authUser);
  if (user) {
    console.log("[AppState] profile created successfully");
    dispatch({ type: "SET_AUTH", user });
  } else {
    console.error("[AppState] ensureProfile failed to create profile");
    dispatch({ type: "SET_AUTH_LOADING", loading: false });
  }
