PROBLEM
━━━━━━━━━━━━━━━━━━━━━━━
The current implementation caches createBrowserClient in a singleton (_client). According to @supabase/ssr docs, createBrowserClient must NOT be cached — it must be called fresh each time so it can read the current cookie state. Caching it breaks the PKCE cookie flow.

Additionally, after SIGNED_IN fires and SET_AUTH is dispatched, the app crashes silently with a white screen — likely because createBrowserClient is being called server-side (during SSR) where cookies are not available, throwing an error.

Replace the entire contents of src/lib/supabase.ts with this:

import { createBrowserClient } from "@supabase/ssr";
import { createClient } from "@supabase/supabase-js";

type SupabaseClient = ReturnType;

const REAL_URL = process.env.NEXT_PUBLIC_SUPABASE_URL!;
const ANON_KEY = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!;

function isOrchidsSandbox(): boolean {
  return (
    typeof window !== "undefined" &&
    window.location.hostname.includes("orchids.cloud")
  );
}

// For Orchids sandbox — use proxy URL with standard createClient (no SSR needed)
function getProxyClient(): SupabaseClient {
  const url = `${window.location.origin}/api/proxy`;
  return createClient(url, ANON_KEY);
}

// createBrowserClient must NOT be cached — call fresh each time
// so it reads the latest cookie state for PKCE flow
export function getSupabase(): SupabaseClient {
  if (typeof window !== "undefined" && isOrchidsSandbox()) {
    return getProxyClient() as unknown as SupabaseClient;
  }
  return createBrowserClient(REAL_URL, ANON_KEY) as unknown as SupabaseClient;
}

export function getAuthSupabase(): SupabaseClient {
  return getSupabase();
}

export function getRealtimeSupabase(): SupabaseClient {
  return getSupabase();
}

export function resetSupabaseClient() {
  // no-op — no singleton to reset
}
