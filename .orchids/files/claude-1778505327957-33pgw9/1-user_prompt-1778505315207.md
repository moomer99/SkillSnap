Implement Client/Pro role system on SkillSnap (skillsnap.com.au):

━━━━━━━━━━━━━━━━━━━━━━━
1. DATABASE — add role field
━━━━━━━━━━━━━━━━━━━━━━━
Add a role field to the profiles table in Supabase:
  - Column name: role
  - Type: text
  - Default: null (not set)
  - Allowed values: null, 'client', 'pro'

Run this migration in Supabase SQL Editor:
  ALTER TABLE profiles ADD COLUMN IF NOT EXISTS role text DEFAULT null CHECK (role IN ('client', 'pro', null));

━━━━━━━━━━━━━━━━━━━━━━━
2. PROFILE SETTINGS — role selector
━━━━━━━━━━━━━━━━━━━━━━━
In the profile settings/edit screen, add a role selector:
  - Label: "I am a..."
  - Two options: "Client" and "Pro"
  - Style: two pill/card buttons, selecting one highlights it in purple (#6C63FF)
  - If role is null (not set), neither is selected
  - Saving profile saves the role to the profiles table
  - User can switch between Client and Pro anytime

━━━━━━━━━━━━━━━━━━━━━━━
3. ROLE BADGE — profile and chat only
━━━━━━━━━━━━━━━━━━━━━━━
Show a small role badge in these places ONLY:

ON PROFILE PAGE (own and other user's):
  - Show "Pro" or "Client" badge next to the username
  - Style: small pill, Pro = purple bg (#6C63FF) white text, Client = grey bg white text
  - If role is null, show nothing

IN CHAT THREAD HEADER:
  - At the top of each chat thread, show both participants with their role
  - Format: "John Smith · Client" on one side, "MD Afro · Pro" on the other
  - Small text, muted colour, below the name
  - If role is null, show nothing next to the name

DO NOT show role badge on feed posts — all feed content is from Pros so it's redundant.

━━━━━━━━━━━━━━━━━━━━━━━
4. POSTING RESTRICTION
━━━━━━━━━━━━━━━━━━━━━━━
When a user with role = 'client' OR role = null taps the Post (+) button:
  - DO NOT open the post creation screen
  - Instead show a popup modal with:
    - Title: "Share your work on SkillSnap"
    - Body: "Switch to Pro to post videos and showcase your skills to clients nearby."
    - Primary button: "Switch to Pro" → opens profile settings role selector
    - Secondary button: "Maybe later" → dismisses popup
  - Style: white bg, border-radius 16px, centred modal on desktop, bottom sheet on mobile
  - Only users with role = 'pro' can access the post creation screen

━━━━━━━━━━━━━━━━━━━━━━━
5. FIRST TIME SETUP — gentle prompt
━━━━━━━━━━━━━━━━━━━━━━━
When a logged-in user has role = null (not set yet):
  - Show a dismissible banner at the top of the feed:
    - Text: "Complete your profile — let people know if you're a Client or Pro"
    - Button: "Set my role" → opens profile settings role selector
    - Dismiss (✕) button to close the banner
  - Style: soft purple background (#EEF0FF), purple text, rounded, full width of feed column
  - Only show once per session — if dismissed, don't show again until next visit
  - Once role is set, banner disappears permanently

━━━━━━━━━━━━━━━━━━━━━━━
6. UPDATE USER TYPE in AppState
━━━━━━━━━━━━━━━━━━━━━━━
Make sure the role field is included when:
  - Fetching the profile (SELECT * already covers it if column exists)
  - Mapping the profile in mapProfile() in authService.ts — add: role: (profile.role as string | null) ?? null
  - The User type in types.ts — add: role: 'client' | 'pro' | null

Do not change any colours, fonts, feed layout, or other functionality.
