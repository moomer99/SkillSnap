PART 1 — ROLE/SKILL FLOW REDESIGN
━━━━━━━━━━━━━━━━━━━━━━━

1A. REMOVE the separate "I am a..." Client/Pro buttons from profile settings entirely. Role is now determined by skill selection only.

1B. UPDATE the Skill Category selector in profile settings:
Add "Client" as the first option in the skill category list, before all other skills.
The full list should be: Client, Barber, Tiler, Makeup Artist, Cleaning, Fitness/PT, Plumber, Electrician, Landscaping, Nails, Other

1C. ROLE LOGIC based on skill selection:
  - User selects "Client" → role = 'client', skill = null
  - User selects any other skill (Barber, Plumber, etc.) → role = 'pro', skill = selected skill
  - User selects "Other" and types custom skill → role = 'pro', skill = custom text
  - Save both role and skill to the profiles table on save

1D. PROFILE DISPLAY — show skill/role badge:
  - Pro: show their skill as badge (e.g. "Barber") on profile and in chat
  - Client: show "Client" as badge on profile and in chat
  - Null/not set: show nothing

1E. AFTER SIGNUP — mandatory role setup screen:
  - After a new user signs up, before they see the feed, show a full screen prompt:
    - Title: "What brings you to SkillSnap?"
    - Subtitle: "Choose your role to get started"
    - Show the skill category list as large tappable cards
    - User MUST select one before continuing
    - On selection → save to profile → navigate to feed
  - This screen only shows once — if role is already set, skip it

1F. POSTING RESTRICTION:
  - If user role = 'client' OR role = null → tapping Post (+) shows popup:
    - Title: "Share your work on SkillSnap"
    - Body: "Switch to Pro to post videos and showcase your skills to clients nearby."
    - Button: "Update Profile" → opens profile settings skill selector
    - Button: "Maybe later" → dismisses
  - Only role = 'pro' users can access post creation screen

1G. CHAT — show role/skill badge in thread header:
  - At top of each chat thread show both participants with their skill/role
  - Pro: shows skill (e.g. "Barber"), Client: shows "Client"
  - Small text below name, muted colour

PART 2 — FIX JOBS DONE BUG
━━━━━━━━━━━━━━━━━━━━━━━
The jobs_done table and notifications table both exist but are completely empty — the frontend is never inserting rows when a pro requests Jobs Done.

Database schema (already exists, do not recreate):
jobs_done: id, skiller_id, client_id, conversation_id, description, skiller_confirmed, client_confirmed, verified_at, created_at
notifications: id, user_id, type, from_user_id, message, read, created_at

2A. FIX — when pro taps "Request Jobs Done" in chat:
  - Insert a row into jobs_done table:
    - skiller_id = pro's user id
    - client_id = other participant's user id
    - conversation_id = current conversation id
    - skiller_confirmed = true
    - client_confirmed = false
    - created_at = now()
  - Insert a row into notifications table:
    - user_id = client's user id (receiver)
    - type = 'jobs_done_request'
    - from_user_id = pro's user id
    - message = 'requested a Jobs Done confirmation'
    - read = false
    - created_at = now()
  - Show confirmation to pro: "Jobs Done request sent!"

2B. FIX — client receives and sees the request:
  - Use Supabase Realtime to subscribe to notifications table for the current user
  - When a new notification with type = 'jobs_done_request' arrives:
    - Show a banner or popup in the chat thread:
      - "Pro name has requested a Jobs Done confirmation"
      - Two buttons: "Confirm" and "Decline"
  - On Confirm:
    - Update jobs_done row: client_confirmed = true, verified_at = now()
    - Increment jobs_done count on pro's profile: UPDATE profiles SET jobs_done = jobs_done + 1 WHERE id = skiller_id
    - Mark notification as read: read = true
    - Show success message to both users
  - On Decline:
    - Delete the jobs_done row
    - Mark notification as read
    - Show declined message

2C. FIX — jobs_done count on profile:
  - The jobs_done count shown on profile and feed posts should read from profiles.jobs_done column
  - Make sure it updates in real time when a Jobs Done is confirmed

2D. ADD RLS policies if missing — the insert into jobs_done and notifications must be allowed for authenticated users:
  Run in Supabase SQL Editor:
  
  CREATE POLICY "Users can insert jobs_done" ON jobs_done FOR INSERT WITH CHECK (auth.uid() = skiller_id);
  CREATE POLICY "Users can update jobs_done" ON jobs_done FOR UPDATE USING (auth.uid() = client_id OR auth.uid() = skiller_id);
  CREATE POLICY "Users can insert notifications" ON notifications FOR INSERT WITH CHECK (auth.uid() = from_user_id);
  CREATE POLICY "Users can read own notifications" ON notifications FOR SELECT USING (auth.uid() = user_id);
  CREATE POLICY "Users can update own notifications" ON notifications FOR UPDATE USING (auth.uid() = user_id);

Do not change any colours, fonts, feed layout, or other unrelated functionality.
