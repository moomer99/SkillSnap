BUG 1 — Jobs Done insert fails: missing required values
━━━━━━━━━━━━━━━━━━━━━━━
Console confirms:
  [ChatScreen] handleRequestJobDone: missing required values

The handleRequestJobDone function is being called but conversation_id or client_id is null/undefined at the time of the insert.

Fix:
1. Find handleRequestJobDone in the chat screen component
2. Log ALL values before the check: console.log('[JobsDone] values:', { skiller_id, client_id, conversation_id, thread, activeThreadId })
3. The conversation_id must be sourced from the active thread/conversation — check where it comes from and make sure it is passed correctly to handleRequestJobDone
4. The client_id must be the OTHER participant's user id (not the current user) — verify this is correct
5. Once values are confirmed present, do the insert:

  const { data, error } = await getAuthSupabase()
    .from('jobs_done')
    .insert({
      skiller_id: currentUser.id,
      client_id: otherParticipant.id,
      conversation_id: conversationId,
      skiller_confirmed: true,
      client_confirmed: false,
    })
    .select()
    .single();
  
  console.log('[JobsDone] insert result:', data, error);
  if (error) console.error('[JobsDone] insert failed:', error.message, error.code);

6. After successful insert, insert into notifications:

  await getAuthSupabase()
    .from('notifications')
    .insert({
      user_id: otherParticipant.id,
      type: 'jobs_done_request',
      from_user_id: currentUser.id,
      message: currentUser.displayName + ' requested a Jobs Done confirmation',
      read: false,
    });

7. Also insert a persistent message into the messages table so it survives navigation:
  Insert a message with type 'system' or a special flag, text: 'Jobs Done requested — waiting for confirmation'
  This must be saved to the database, not just local state

BUG 2 — Realtime subscription error causing chat reload loop
━━━━━━━━━━━━━━━━━━━━━━━
Console error:
  "cannot add postgres_changes callbacks for realtime:messages after subscribe()"

This is caused by trying to add listeners to an already-subscribed Realtime channel. The chat is reloading threads repeatedly because of this.

Fix:
1. Find where subscribeToMessages is called in the chat screen
2. Before subscribing, check if a channel for this conversation already exists and unsubscribe it first:
  const existingChannel = supabase.getChannels().find(c => c.topic === channelName)
  if (existingChannel) await supabase.removeChannel(existingChannel)
3. Then subscribe fresh
4. On component unmount, always unsubscribe and remove the channel
5. Make sure subscribeToMessages is not called multiple times for the same conversation — add a ref to track if already subscribed
