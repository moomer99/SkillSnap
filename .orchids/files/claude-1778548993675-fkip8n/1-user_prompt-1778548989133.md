FIX 1 — Receiver notification UI
━━━━━━━━━━━━━━━━━━━━━━━
1A. Add unread notification badge on Messages nav icon:
  - On app load for logged-in users, fetch unread notifications count:
    SELECT count(*) FROM notifications WHERE user_id = currentUser.id AND read = false
  - Show a red badge with the count on the Messages nav icon
  - Subscribe to notifications table via Supabase Realtime for new inserts:
    filter: user_id=eq.[currentUser.id]
  - When a new notification arrives, increment the badge count

1B. When user opens the Messages/chat screen:
  - Fetch any unread notifications for the current user
  - For each notification with type = 'jobs_done_request':
    - Find the chat thread matching the from_user_id
    - Show a special card/banner at the top of that thread in the messages list:
      - "[Name] requested a Jobs Done confirmation"
      - "Confirm" button (green) and "Decline" button (red)
    - On Confirm:
      - Update jobs_done row: client_confirmed = true, verified_at = now()
      - UPDATE profiles SET jobs_done = jobs_done + 1 WHERE id = skiller_id
      - Mark notification as read: UPDATE notifications SET read = true
      - Show success message: "Jobs Done confirmed! ✓"
      - Remove the banner
    - On Decline:
      - Delete the jobs_done row
      - Mark notification as read
      - Remove the banner

1C. Mark all notifications as read when user opens messages screen

FIX 2 — Jobs Done message persistence in chat
━━━━━━━━━━━━━━━━━━━━━━━
Do NOT try to insert into the messages table for this.

Instead, when loading a chat thread, also fetch any pending jobs_done requests for that conversation:

  SELECT * FROM jobs_done 
  WHERE conversation_id = [conversationId]
  AND skiller_confirmed = true 
  AND client_confirmed = false
  ORDER BY created_at DESC
  LIMIT 1

If a pending row exists, show a special persistent card in the chat (above the message input):
  - For the PRO (sender): "Jobs Done request sent — waiting for [client name] to confirm"
  - For the CLIENT (receiver): "[Pro name] requested a Jobs Done confirmation" + Confirm/Decline buttons
  - This card stays visible as long as the jobs_done row has client_confirmed = false
  - When client confirms or declines, remove the card

This approach reads directly from the jobs_done table on every chat load — no dependency on message persistence.

Do not change any colours, fonts, feed layout, or other unrelated functionality.
