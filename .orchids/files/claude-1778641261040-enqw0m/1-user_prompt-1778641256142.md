Fix the rating system so that when a client submits feedback after confirming a job, 
the rating is saved to Supabase and the pro's happy_percent on their profile updates permanently.

PROBLEM: In ChatScreen.tsx, handleSubmitFeedback() only updates local state via dispatch. 
It never saves to Supabase, so ratings are lost on refresh and the pro's profile never updates.

CHANGES NEEDED:

1. CREATE a new Supabase table called "ratings":
   - id (uuid, primary key, default gen_random_uuid())
   - job_id (uuid, references jobs_done.id)
   - skiller_id (uuid, references profiles.id) — the pro being rated
   - client_id (uuid, references profiles.id) — who submitted the rating
   - rating (text) — values: 'very_happy', 'okay', 'not_satisfied'
   - is_happy (boolean) — true for very_happy/okay, false for not_satisfied
   - comment (text, nullable)
   - created_at (timestamptz, default now())
   Enable RLS. Add policy: authenticated users can INSERT their own rating 
   (client_id = auth.uid()). Add policy: anyone can SELECT.

2. CREATE a Supabase DB trigger (or use existing handle_job_confirmed pattern) 
   that after INSERT on ratings, recalculates the skiller's happy_percent:
   UPDATE profiles SET 
     happy_percent = (
       SELECT ROUND(
         COUNT(*) FILTER (WHERE is_happy = true) * 100.0 / NULLIF(COUNT(*), 0)
       )
       FROM ratings WHERE skiller_id = NEW.skiller_id
     )
   WHERE id = NEW.skiller_id;

3. IN ChatScreen.tsx, update handleSubmitFeedback() to save the rating to Supabase 
   BEFORE the local dispatch. Add this block after "const ratingData = RATINGS.find(...)":

   if (SUPABASE_CONFIGURED && activeJobId) {
     try {
       const { getAuthSupabase } = await import("@/lib/supabase");
       await getAuthSupabase()
         .from("ratings")
         .insert({
           job_id: activeJobId,
           skiller_id: displayParticipant.id,
           client_id: currentUser?.id,
           rating: ratingData.key,
           is_happy: ratingData.happy,
           comment: comment.trim() || null,
         });
     } catch (e) {
       console.warn("[ChatScreen] rating insert failed:", e);
     }
   }

4. After the rating insert, re-fetch the skiller's updated happy_percent from profiles 
   and dispatch UPDATE_PARTICIPANT_HAPPY with the real DB value instead of the 
   locally calculated one. Pattern already exists in handleClientConfirm — follow same approach.

Do not change any UI. Do not change the rating modal design. Only fix the data persistence.
