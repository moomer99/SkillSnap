I want guests to be able to browse the feed without signing in. When they try to do something that requires an account (Connect, Post, Profile, Chat, etc.), show the existing auth prompt.

isGuest: boolean;

// In initialState, add:
isGuest: false,

// In the reducer, add a new case:
case "CONTINUE_AS_GUEST":
  return { ...state, isGuest: true, showAuthPrompt: false };

// Also add SIGN_OUT / SIGN_IN should reset isGuest to false (wherever auth success is handled)

4. src/components/skillsnap/HomeFeed.tsx (and any other screen)
The requireAuth function already does:
tsfunction requireAuth(action) {
  if (!state.isAuthenticated) { dispatch({ type: "SHOW_AUTH_PROMPT" }); return; }
  action();
}
Update this to also allow guests through on browse-only actions, but block on write actions (Connect, Post, Chat):
tsfunction requireAuth(action) {
  if (!state.isAuthenticated && !state.isGuest) {
    dispatch({ type: "SHOW_AUTH_PROMPT" }); return;
  }
  action();
}

function requireFullAuth(action) {
  if (!state.isAuthenticated) {
    dispatch({ type: "SHOW_AUTH_PROMPT" }); return;
  }
  action();
}
Use requireFullAuth for: Connect button, Post button, Chat, Profile editing.
Use requireAuth (guest allowed) for: viewing feed, viewing profiles.

5. Desktop sidebar: src/components/skillsnap/RightSidebar.tsx
The existing "Join SkillSnap / Sign Up Free / Log In" card should still show for guests. No change needed here — state.isAuthenticated is already false for guests so the card will show.

Summary of the full guest flow:

User lands on LandingPage → taps "Continue as guest"
isGuest = true, navigate to home feed
Feed is fully browsable — posts, profiles, discover all work
Tapping Connect / Post / Chat → SHOW_AUTH_PROMPT fires → sign-in overlay appears with the existing "Join SkillSnap" UI
